## R1｜仓库骨架与数据库连接

```text

需要：
1. 目录结构 src/app、src/lib、src/components、src/server、public/uploads、data。
2. src/server/db.ts：用 better-sqlite3 打开 process.env.DATABASE_PATH（默认 ./data/campus.db），开启 foreign_keys 与 WAL；导出单例 db。
3. src/server/schema.sql：按我给的 9 张表建表（CREATE TABLE IF NOT EXISTS），含 items 的三个索引，字段类型和默认值严格按 docs/03-数据库设计.md（我贴在下面）。
4. src/server/migrate.ts：读取 schema.sql 执行，导出 `npm run migrate` 脚本。
5. .env.example、.gitignore（忽略 node_modules、.env.local、data/*.db、public/uploads/*，保留 .gitkeep）。
```

**验收**：`npm run dev` 打开首页正常；`npm run migrate` 后 `data/campus.db` 生成，用 `sqlite3 data/campus.db ".tables"` 能看到 9 张表。
**commit**：`chore: Next.js 骨架 + SQLite 连接与建表脚本`

## R2｜注册与登录（含会话）

```text
实现注册与登录，服务端校验，不用任何鉴权库。
1. src/server/auth.ts：hashPassword(pw) 用 node:crypto scrypt + 16 字节随机盐，返回 "salt:hash" 的 hex；verifyPassword 用 timingSafeEqual；signSession(userId) 生成 HMAC 签名 token；requireUser(req) 从 httpOnly cookie 解析出当前用户，失败返回 401。
2. POST /api/auth/register：校验 username 4-20 位、password ≥6 位、nickname 非空；username 已存在返回 409；成功后直接签发登录 cookie。
3. POST /api/auth/login：错误统一返回「用户名或密码错误」，不区分哪个字段错。
4. POST /api/auth/logout 清除 cookie。
5. 页面 /login 与 /signup：粉彩卡片居中表单，错误信息红字提示，提交后跳回来源页或首页。
6. 顶部导航组件：未登录显示「登录/注册」，已登录显示昵称下拉（我的、退出）。用户信息通过服务端 layout 读取 cookie 后作为 props 传入，不要在前端调 /api/me。
```
**验收**：注册 → 自动登录 → 刷新后仍是登录态 → 退出后 /api 写接口返回 401。
**commit**：`feat: scrypt 注册登录与 httpOnly 会话`

## R5｜收藏 + 申领单 + 状态机

```text
1. 收藏：POST /api/items/[id]/favorite 切换（有则删、无则插），卡片与详情页显示是否已收藏（服务端渲染时查）。
2. 申领：POST /api/items/[id]/applications 建 application（status=pending），校验：不能申领自己的物品、物品必须 listed、同一用户对该物品只能有一条非 cancelled 记录；donate 物品要求填 reason。
3. 物品主人在 /me 里可 同意(approved)/拒绝(rejected)；同意后 items.status='reserved'。
4. 主人点「已完成交割」→ application.status='completed'、items.status='completed'；若 mode='donate' 则同时向 donations 插一条（green_weight_kg 按 docs/03 的系数表用 category 计算，系数放 src/lib/green-factors.ts）。
5. 任一方取消 → cancelled，若该物品无其他进行中申领则 items.status 回到 listed。
6. 状态流转写成 src/server/item-state.ts 的纯函数 + 单元测试（用 node:test，加 npm test 脚本），把状态机集中管理，不要在路由里散落 if。
```
**验收**：两个账号跑通「申领 → 同意 → 完成」，donate 物品完成后 donations 表多一条且 status 正确。
**commit**：`feat: 收藏与申领状态机（含状态流转单测）`

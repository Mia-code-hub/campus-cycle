## R18｜AI 环保报告生成

```text
1. POST /api/ai/report：入参无，服务端取 getOverview/trend/category，把数字以 JSON 形式塞进 prompt，要求 qwen-plus 输出一篇 600-900 字的校园闲置循环环保报告（Markdown），结构：概述 / 数据事实 / 公益成效 / 改进方向。
2. 硬约束写进 prompt：所有数字必须原样引用给到的 JSON，禁止新增或推算任何未提供的数据；不得虚构学校名称与个人姓名。
3. 服务端拿到结果后做一次校验：把报告里出现的所有数字与源数据比对，不匹配则标记 status=parse_error 并返回错误，不展示可疑内容。
4. 报告展示在 /admin/report 页（Markdown 渲染，粉彩信纸卡片），提供「导出 PDF」用浏览器打印样式（@media print 去掉导航与按钮）。
5. 台账导出：GET /api/admin/donations/export.csv，UTF-8 BOM 防止 Excel 乱码，列含日期、物品、类别、捐赠人、受赠人（匿名处理）、折算重量。
```
**commit**：`feat: AI 环保报告生成与台账 CSV 导出`

## R20｜安全与健壮性复查

```text
逐项检查并修复，输出「发现的问题 + 改法」清单：
1. 所有写接口是否 requireUser/requireAdmin；有无越权（改别人的物品、看别人的私信、读别人的 donationId）。
2. SQL 是否全参数化；LIKE 查询是否转义 % 与 _。
3. 上传：类型白名单、大小限制、随机文件名、禁止路径穿越（用户传入的 image_path 要校验前缀）。
4. Cookie：httpOnly + sameSite=lax + secure（生产）；SESSION_SECRET 缺失时启动即报错而不是用默认值。
5. AI 接口加简单限流（内存 Map 按 userId 每分钟 N 次），超限返回 429，防止我答辩时手快点爆额度。
6. 所有对外错误响应不泄漏堆栈与 SQL 片段。
```
**commit**：`fix: 越权校验、上传与 SQL 安全加固、AI 接口限流`

# 阶段 3 · AI 能力（R9–R15，每轮一次 commit）

> 这一阶段是比赛得分核心（过程可复现 25% + 意图控制 20%）。
> **每一轮都要求 AI 把 prompt 原文写进 `src/lib/ai/prompts.ts` 常量**，这样 prompt 演进历史全部留在 git diff 里 —— 答辩时直接翻 commit 记录给你加分。

## R9｜百炼调用底座 + 调用留痕

```text
1. 用 npm 安装 openai SDK，写 src/lib/ai/client.ts：导出 chat(opts) 与 embed(texts)，baseURL 与 key 从 process.env 读，默认超时 15s（AbortController），失败抛出带 kind 字段的错误（api_error|timeout|parse_error）。
2. 写 src/lib/ai/log.ts：logAiCall({feature, model, userId, refItemId, prompt, raw, parsed, latencyMs, status})，写 ai_call_logs 表；提供 getRecentCalls(feature, limit) 供管理端查看。
3. 写 src/lib/ai/prompts.ts：本轮只放 SYSTEM_BASE 常量（角色设定：校园闲置物品信息整理助手，必须输出 JSON，禁止编造图片中不存在的品牌/版本/型号，中文回答）与一个 buildAnalyzePrompt(...) 空实现占位。
4. 写 src/lib/ai/json.ts：safeParseJson(raw) 处理模型返回带 ```json 包裹、前后有解释文字、字段缺失的情况；解析失败返回 null 而不是抛异常。
5. 所有 AI 路由统一走 withAiLog 高阶函数：负责计时、落库、错误降级，业务代码不重复写 try/catch。
6. 加一个自检接口 GET /api/ai/health：传一句 prompt 让 qwen-plus 回 "ok"，返回耗时与模型名，用于我确认 key 配好了。
```
**验收**：`curl` 调 /api/ai/health 返回 ok；`ai_call_logs` 有记录。
**commit**：`feat: 百炼调用底座、超时降级与 ai_call_logs 留痕`

## R10｜VLM 识图 + 文案 + 成色

```text
实现 POST /api/ai/analyze 的图像理解部分（不含估价）。
1. buildAnalyzePrompt(rawDesc, mode, historyPrices) 生成 messages：system 用 SYSTEM_BASE；user 为多模态数组 [image_url(dataURL), text(指令)]。
2. 指令要求严格输出 JSON：{"category":"textbook|bedding|stationery|appliance|daily|clothing|other","conditionLevel":"95新|9成新|8成新|可用","title":"...","aiDesc":"...","tags":["..."]}，title ≤22 字，aiDesc 60-110 字，tags 3-6 个，只描述图片与描述中确实存在的信息。
3. 给两条少样本示例（教材、台灯）放进 prompt，提升格式稳定性。
4. 调 qwen-vl-max，safeParseJson 解析，枚举值做白名单校验（非法值归为 other/可用），失败则 status=parse_error 并返回 502 且 degraded=true。
5. 图片压缩：前端上传前用 canvas 压到最长边 1024px、jpeg 质量 0.8 再转 dataURL，减少 token 与耗时。
6. 发布页接上：点「AI 帮我完善」→ 按钮变「AI 正在识别…」+ 骨架屏 → 回填表单各字段，每个字段右上角出现「AI」小徽章，用户手动改动后徽章变「已修改」并把 items.ai_edited 置 2。
```
**验收**：拍一张课本照片 + 「高数课本 写过几页」→ 返回合理类别/成色/文案；断网或填错 key 时表单仍可手填提交。
**commit**：`feat: qwen-vl-max 识图生成类别成色与文案`

## R11｜参考定价（数据增强）

```text
给 analyze 补估价能力，不许调用外部行情接口。
1. src/server/price-stats.ts：getCategoryPriceStats(category) 用 SQL 聚合同类目 status='completed' 且 mode='sale' 的 price，返回 { count, avg, min, max }；样本 < 3 时标记 insufficient=true。
2. buildAnalyzePrompt 增加 historyPrices 上下文段：「本校同类目历史成交：N 件，均价 X 元，区间 [min,max]」。样本不足时改为注入内置参考价表 src/lib/ref-price.ts（教材 0.3 折、小家电 5 折等，按原价百分比给区间，注明为经验值）。
3. 输出 JSON 增加 "priceRange":{"low":..,"high":..,"suggested":..}，并加一句 "priceReason":"..."（≤40 字，说明依据）。
4. mode=donate 时不估价，改为生成 "donateTag"（如「教材援助 · 让知识继续流转」），要求 8-16 字、积极不煽情。
5. 前端：定价下方画一条参考区间条（low—high 渐变，suggested 打点），可点击把 suggested 填入价格框；捐赠模式下隐藏价格输入、显示 AI 生成的公益标签。
```
**验收**：seed 数据下 textbook 类有成交记录 → 返回区间合理；donate 模式返回公益标签。
**commit**：`feat: 基于校内成交聚合与参考折扣的 AI 估价`

## R12｜向量化与语义检索

```text
实现供需智能匹配。
1. src/lib/ai/embed.ts：embedItem(itemId) 把 title + ai_desc + raw_desc + category + condition_level + ai_tags 拼成一段文本，调 text-embedding-v3（dimension 1024），Float32Array → Buffer 存 items.embedding，写 embedded_at。
2. src/lib/ai/vector.ts：serializeVector/deserializeVector 与 cosineSimilarity(a,b) 纯函数 + node:test 单测（含正交、同向、零向量三种用例）。
3. src/server/retrieval.ts：searchItems(queryVec, { topK, viewerId }) —— 全表载入 listed 物品的 embedding 算余弦，业务加权：donate +0.15、viewer 为通过审核的帮扶生且物品为 donate 则 +0.30、completed 排除；返回带 similarity 与 matchLabel（≥0.75 高度匹配 / ≥0.6 较匹配 / 其他 相关）。
4. POST /api/ai/search：query 向量化 → searchItems → 取 Top-8 交给 qwen-plus 生成 60-100 字导购语（要求：只依据给到的物品事实，不得承诺库存与价格，不得编造）→ 返回 { guide, items }。
5. /search 页：顶部 AI 导购卡片（带打字机式逐字显示，纯 CSS/JS 实现），下方结果卡片复用首页样式，每张卡右上角显示匹配度百分比；无结果时显示放宽建议与 /donate 入口。
6. 发布成功后服务端自动 embedItem；items 的 title/描述被用户修改时置空 embedded_at，列表页加载时对缺向量的记录补算（后台串行，不阻塞响应）。
```
**验收**：搜「有没有便宜点的高数课本」能召回教材类；帮扶生账号搜捐赠教材时 donate 结果排前。
**commit**：`feat: 物品向量化与语义检索召回（含业务加权）`

## R13｜违规内容审核

```text
实现发布前置审核。
1. POST /api/ai/moderate：入参 title/desc/image(可选 dataURL)，用 qwen-vl-max（有图）或 qwen-plus（无图）判定，严格输出 {"pass":true|false,"category":"ok|prohibited|dangerous|medical|animal|indecent|offcampus","reason":"...","confidence":0-1}。
2. prompt 中列明平台规则：校内自用闲置、禁止药品与医疗器械、禁止管制刀具与易燃易爆、禁止活体动物、禁止涉黄涉政、疑似校外批量倒卖（同一人一次挂 10 件以上全新同款）需人工复核；要求 reason ≤50 字且指出命中规则。
3. 服务端二次兜底：本地关键词表 src/lib/banned-terms.ts 命中直接拦截（不依赖模型可用性），模型结果与本地结果冲突时以「更严格」的一方为准并记录。
4. 发布流程接入：提交前先 moderate，pass=false 时阻断、展示类别与原因、允许修改后重试；模型故障（api_error/timeout）时放行但 items.violation_flag=2 标记待人工复核。
5. 管理员 /admin/violations 列表：展示 violation_flag>0 的物品、AI 理由、命中的本地关键词，提供「人工下架 / 恢复上架」按钮（改 status 与 violation_flag）。
```
**验收**：描述写「转让一盒处方消炎药」被拦截；把 key 改错后正常物品仍能发布且被标记待复核。
**commit**：`feat: AI 违规审核 + 本地关键词兜底与人工复核`

## R14｜捐赠感谢信生成

```text
1. POST /api/ai/letter：入参 { donationId }，服务端自查 donations + items + users 组装上下文，不接受前端传隐私字段。
2. 生成要求：200-300 字，收信人是捐赠人，落款「校园闲置物资循环平台 + 日期」；语气平视、真诚、不煽情、不出现「贫困/困难/资助」等标签化词，不透露受赠人姓名学院等可识别信息；受赠人选择匿名时以「一位受益于你的同学」自称；允许提及物品类别与「校内继续流转」的意义。
3. 结果写 letters 表（含 receiver_anonymous），donation_id 唯一，重复请求返回已存在的那封（幂等）。
4. /letters/[id] 展示页：信纸样式（米白底、衬线字体、轻阴影、顶部平台徽章），右上角「下载为图片」用 html2canvas 或纯前端 canvas 导出 PNG。
5. 捐赠完成流程自动触发一次生成，台账「查看感谢信」按钮跳转该页。
```
**验收**：完成一笔捐赠后能打开感谢信页并导出 PNG；再次点击不重复生成。
**commit**：`feat: 电子感谢信生成与信纸展示`
